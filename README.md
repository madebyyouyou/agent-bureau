# Agent Bureau

> 把 Claude Code、Codex、Gemini CLI 等**真实终端 CLI 进程**编排成微信式群聊里的 AI 开发团队——全员并行消化任务、按发言权轮流发言、互相评审咨询、显式交接任务、协同改代码，人随时插话、熔断、回滚。

区别于"主 Agent 临时调用子 Agent"的树状执行模式，本系统将各 CLI 作为**长期在线的一等协作者**：各自保有独立会话、角色、工具与代码权限。编排对象是 PTY 终端进程而非模型 API——没有结构化输出、没有回调、注入即模拟击键——因此没有任何现成框架可参考，调度、协议、上下文注入、回滚体系均从零设计。

## 项目状态

**可运行原型 · 持续迭代中**（v0.6.3）。两周内从 v0.1 迭代 30+ 个版本，驱动两个 4 成员生产群持续使用；曾以「前端主程 / 工程执行 / 视觉美术 / 评审」4 个 AI 成员约 34 小时协作交付一个可玩的 Phaser + TypeScript 模拟经营游戏核心闭环。

## 核心功能

- **群聊式多 Agent 协作**：群消息并行广播进全员上下文，发言权按序串行授予；@点名优先插队；成员间经受控的 ask 通道互相咨询，往来自动留档供人旁听。
- **显式任务交接协议**：成员收尾发言三选一——【交接】（@接手人 + 完成事项/交付物/请求三要素）/【完结】/【上报】；被交接人须接下或退回，退回两次自动上报，杜绝"干完即抛"。
- **双通道输出协议**：思考过程与工具调用留在终端"工作日志"，仅约定标签（`<group_message>` 等）内的内容路由进群；信封正文原样入账，清洗只作用于无信封的兜底通道。
- **系统提示层身份注入**：团队章程 + 角色卡拼进各 CLI 启动参数（claude `--append-system-prompt` / codex `-c developer_instructions=`），上下文压缩不丢、会话接续自动携带最新版。Windows 上绕开 `cmd.exe` 直接 spawn 真实可执行文件，否则章程里的尖括号会被当成重定向、换行会截断命令行（见[案例：被命令行绞碎的系统提示](docs/case-study-arg-injection-windows.md)）；参数无法安全改写或 PTY 进程创建失败时，按 spawn 回执降级为会话内补发。
- **Human-in-the-Loop 管控**：git 按成员轮次记账改动归属，单轮撤销 / 整体回滚后自动群播「更正声明」修正全员认知；近 8 轮改动文件求交预警覆盖冲突；连续 N 轮无人插话自动熔断；工具权限菜单浮出为审批卡。
- **会话与记忆管理**：离线成员带记忆接回（session resume）、全员换脑、克隆群接管换代；工作目录零足迹——不向被管理的项目目录写入任何编排文件。

## 架构与关键技术

```
浏览器（群聊 UI：气泡 / 回执 / 熔断条 / 审批卡 / @选人）
   │ WebSocket
上游 CliDeck 服务端 ←──[幂等补丁集：启动时重打，锚点漂移时报错]
   │  ├─ PTY 会话池（claude / codex / gemini / 中转席…）
   │  ├─ 转写管道（终端流 → 回复块候选稿）
   │  └─ 插件系统 ──→ 本项目插件（app/plugin/）
   │                    ├─ 轮次调度状态机（pump 唯一注入出口）
   │                    ├─ 信封解析 / 路由 + 轮次账本
   │                    ├─ git 快照 / 回滚 / 更正声明 / 冲突预警
   │                    └─ 章程包渲染（→ 补丁拼进 CLI 启动旗）
   └─ 各 CLI 进程：各自的模型、工具、MCP、权限
```

- **串行发言权调度状态机**：消化/发言两阶段、超时轮空、watchdog 兜底；关键架构约束是**全系统唯一注入出口 `pump()`**——事件回调与看门狗只有"提醒权"没有发送权，从结构上消除多路投递死锁。用确定性程序逻辑取代对 LLM 自觉的依赖。
- **零 fork 集成**：集成前系统性逆向 1.3 万行上游源码，产出 8 份接口地图与[技术审计摘要](docs/technical-audit-summary.md)；阻塞疑点逐一完成源码验证与受控运行后才冻结设计。主体功能走上游插件 API，插件 API 无法覆盖处才使用带精确锚点和漂移检测的幂等补丁。
- **自动化测试**：100+ 例（`npm test`，Node 原生 test runner，零第三方依赖）。mock 上游环境 + 自研假时钟全链路验证发言权轮转、广播注入、回执与消息路由；上游补丁采用"套用至 vendor 源码副本 + 事故端到端回放"回归；仓库卫生测试锁定可移植路径、公开配置和包锁一致性。
- **技术栈**：Node.js（内置模块，运行时零第三方依赖）+ 原生 WebSocket 前端 + PowerShell 启动器；上游 [CliDeck](https://github.com/rustykuntz/clideck)（MIT）负责 PTY 工位与终端转写。

## 安装与运行

运行环境：Windows、Node.js ≥ 22、全局安装的 CliDeck，以及至少一个已完成自身登录配置的 CLI（Claude Code / Codex / Gemini CLI）。

```powershell
npm install -g clideck@1.31.24
powershell -ExecutionPolicy Bypass -File .\app\scripts\start.ps1
```

启动脚本会从自身位置解析仓库根目录，将插件同步到 CliDeck 数据目录，套用带精确锚点和结构漂移检测的幂等补丁，按需转发 Windows 系统代理，并在本地服务就绪后打开群聊界面。不要使用 `--host 0.0.0.0` 将 CliDeck 暴露到局域网：其本地控制面没有独立认证。

测试不需要全局 CliDeck 或各家 CLI，也没有项目级第三方依赖：

```powershell
npm test
```
